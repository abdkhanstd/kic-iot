# KIC-IoT: Causal Authorization of Untrusted Setpoint Changes

Code and result data for the paper *KIC-IoT: Causal Authorization of Untrusted Setpoint Changes in
Autonomous IoT Systems under Telemetry Corruption*.

Code by **abdkhan**.

## Overview

IoT controllers increasingly execute setpoint changes proposed by learned and language-model agents, and
they judge those proposals from telemetry an attacker can reach. Keyed Interventional Certificates (KIC)
authorize a proposed move only if the plant's own response to a small secret dither certifies that the move
lowers the expected operating cost. The dither is drawn from a keyed pseudo-random function, so a forger who
cannot observe it before committing the forgery cannot bias the certificate. Anytime-valid confidence
sequences keep the guarantee over a whole deployment.

This repository contains:

* the KIC gate, its certificates and the interval certifiers of its premises,
* three simulated plants: an edge-cluster structural causal model (SCM), a mobile-edge-computing (MEC)
  offloading node and the IEEE 33-bus distribution feeder,
* the causal-AI pipeline (discovery, federation, distillation into small language models) that serves as the
  untrusted proposer,
* every experiment script and the JSON/CSV files behind the paper's tables and figures,
* a C port of the gate with a processor-in-the-loop harness for five emulated microcontrollers.

## Installation

Python 3.11 or newer.

```bash
python -m venv .venv
source .venv/bin/activate          # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` pins the versions that produced the released results. The language-model part of the
pipeline (distillation, the LLM proposer study) also needs PyTorch, transformers, peft, datasets,
stable-baselines3 and gymnasium. `constraints.txt` lists the CUDA builds used. The KIC results do not depend
on these packages.

Quick check:

```bash
pip install pytest
python -m pytest tests                               # gate, certificates, plants, feeder power flow
python scripts/save_kic_manifest.py --verify         # every result and source file against its SHA-256
```

## Data

No dataset is redistributed here. The data are either generated by the code or downloaded from their
original sources.

**Synthetic edge-cluster data** (used by the SCM experiments). The generator is seeded, so the files are
reproduced exactly:

```bash
python src/simulator/generate_dataset.py --n_train 20000 --n_test 5000 --n_probes 2000
```

This writes `data/synthetic/clean_train.csv`, `clean_test.csv` and the interventional probes.

**Distillation corpora** (only for the language-model proposer):

```bash
python src/distillation/build_corpus.py --n_train_interventional 4000 --n_train_proposal 2000 \
                                        --n_val_interventional 400 --n_val_proposal 200
python src/attacks/corpus_poisoning.py --fraction 0.2 --seed 0     # poisoned corpus
python experiments/prepare_federated_distillation.py               # local- and fused-graph corpora
```

**N-BaIoT** (real IoT traffic, used only by the causal-discovery evaluation on real data). Download it from the
UCI Machine Learning Repository,
<https://archive.ics.uci.edu/dataset/442/detection+of+iot+botnet+attacks+n+baiot>, unpack the per-device
archives into `data/raw/nbaiot/`, and preprocess:

```bash
python src/utils/preprocess_nbaiot.py --n_per_file 2000
```

**Base language models.** Qwen2.5-0.5B-Instruct and Qwen2.5-1.5B-Instruct, from Hugging Face or ModelScope:

```bash
python src/distillation/fetch_base_model.py Qwen/Qwen2.5-0.5B-Instruct
python src/distillation/fetch_base_model.py Qwen/Qwen2.5-1.5B-Instruct
```

The LoRA adapters are trained with `src/distillation/train_lora.py` and are not included.

**IEEE 33-bus feeder.** pandapower's `case33bw`, installed with pandapower.

## Reproducing the results

Each command writes the named file to `experiments/results/`. Run the scripts from the repository root unless
a command changes directory. Most studies use a process pool. Set `--procs` (or `PROCS` for the shell
drivers) to suit the machine, and `OMP_NUM_THREADS=1` keeps numerical libraries from oversubscribing it.

| Paper | Command | Result file(s) |
|---|---|---|

## Firmware

`firmware/src/kic_gate.c` is a C port of the gate. `firmware/host_replay.py` compiles it natively and replays
the Python closed loop tick by tick (no emulator needed). `firmware/pil.py` and `firmware/pil_baselines.py`
run the same replay on five microcontrollers emulated in [Renode](https://renode.io): STM32F072 (Cortex-M0),
CC2538 (Cortex-M3), nRF52840 (Cortex-M4F), STM32F407 (Cortex-M4F) and FE310 (RV32IMAC).

Tools: Renode 1.17.0, the xPack `arm-none-eabi-gcc` 15.2.1 and `riscv-none-elf-gcc` 15.2.0 toolchains
(<https://xpack-dev-tools.github.io/>). Point `KIC_TOOLS` at the folder that holds them:

```bash
python firmware/host_replay.py
KIC_TOOLS=/path/to/tools python firmware/pil.py --scenarios clean a1_telemetry spoof_blind
KIC_TOOLS=/path/to/tools python firmware/pil_baselines.py --out pil_base/light.json
```
